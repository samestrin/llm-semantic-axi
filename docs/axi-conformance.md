# AXI conformance

Where `llm-semantic` stands against the ten principles on [axi.md](https://axi.md). This table is the current record; [axi-audit.md](axi-audit.md) is the snapshot it replaced.

| # | Principle | Status | Notes |
|---|---|---|---|
| 1 | Token-efficient output (TOON) | Met | TOON is the default output of every command. `--json` (JSON) and `--plain` (human-readable text) each replace it; `--axi` is still accepted as an alias for TOON: on its own it changes nothing, but like any format flag it cannot be combined with another. Contradictory format flags (`--plain --json`, `--axi` with `--json` or `--plain`, or `--min` with `--plain`) exit 2. |
| 2 | Minimal default schemas (3-4 fields per item) | Met | A default search row carries four fields (`file` as `path:line`, `name`, `score`, `content`); `memory search` carries `id`, `question`, `score`, `answer`; `memory list` carries `id`, `question`, `status`, `answer`; `memory stats` carries `id`, `question`, `retrieval_count`, `avg_score`; `callers` carries `file` (as `path:line`), `name`, `ref`; `refs` carries `file` (as `path:line`), `ref`, `resolved`, `type`, with external references omitting `file`. `--full` opts back into every field. There is no `--fields` flag to pick fields one by one, as axi.md suggests: the choice is the compact default or every field with `--full`. |
| 3 | Content truncation with a size hint and `--full` | Met | The default output cuts content over 200 characters and says how many were left out, including the answer `memory store` echoes back in its confirmation. `--full` returns the whole text. The limit is below the 500-1,500 characters axi.md recommends: a search returns a list of ten rows by default, and 200 keeps the whole list small (see [the token benchmark](../benchmarks/results-tokens.md)). |
| 4 | Pre-computed aggregates, always a total | Met | The search family states its `total` (`N results for "query"` under `--plain`); `multisearch` reports `total_queries` and `total_results`; `callers` and `refs` state their `total` in the default TOON output; `memory list` states `total`, and `memory stats` states `total` alongside its pre-computed `total_memories`, `pending` and `promoted` counts, which count every memory in the store, retrieved or not. |
| 5 | Definitive empty states | Met | An empty search says it found nothing (`message`, and `--plain` says so in text), and a search over an index with no chunks says the index is empty instead (`status: index_empty` vs `no_match`). `memory list` and `memory stats` say `status: store_empty` with a message over an empty store, and `no_match` when a filter excludes every entry (or, for stats, nothing has been retrieved yet). `callers`/`refs` distinguish `symbol not indexed`, `not indexed for edges` and a genuine empty answer (see [languages.md](languages.md)). |
| 6 | Structured errors on stdout, exit 0/1, idempotent, never prompt | Met | Every error goes to stdout in the active format: a TOON or JSON object with `error: true`, or `Error: ...` under `--plain`. stderr carries only diagnostics. A failure exits 1, including an `index` or `index-update` run in which any file failed: a partial result still exits 1, and its one TOON or JSON document carries `error: true` and a `message` alongside the counts and the `errors` list naming each failed file; an embedding API that cannot be reached is reported as `cannot reach the embedding API at <url>` with a `help` list saying to start it or set `--api-url` / `LLM_SEMANTIC_API_URL`, not as Go's transport error; a malformed invocation exits 2 and names what was wrong, as axi.md asks ("unknown flags must fail loud"): an unknown flag or command with the valid choices; a missing or extra argument (`missing argument <symbol>`), a missing required flag or a bad flag value (`invalid value "1d" for --older-than: it takes a whole number`) with the right form in the message and a `help` list (`Usage: ...`, an example, `--help`); contradictory format flags with the flags that conflict. Every command declares the arguments it takes, so a stray one (`index-status extra`) is refused rather than ignored. No command prompts: `collection delete` without `--force` and `memory stats --prune` without `--yes` refuse with an error naming the flag and exit 1, deleting nothing. |
| 7 | Ambient context (`setup` command, Agent Skill) | Met, with an exception | `llm-semantic setup` registers a SessionStart hook with Claude Code (`.claude/settings.json`) and Codex (`.codex/hooks.json`, with `[features] hooks = true` in `.codex/config.toml`), and an OpenCode plugin (`.opencode/plugins/llm-semantic.ts`) acting on `session.created`. Each runs `llm-semantic index-status`, its exit status ignored, so a session starts with this directory's index status and a project with no index raises no hook error. `--target` (repeatable) narrows to the named agents. `setup` also writes the Agent Skill to `.claude/skills/llm-semantic/`, and `npx skills add` installs the same skill for other agents, without a hook. No session-end hook is installed, so axi.md's lifecycle capture is not done: the tool keeps no session state to capture, and the index it reads at session start is rebuilt by `llm-semantic index`, not by the session ending. |
| 8 | Content first (no-argument run shows live data) | Met | A bare `llm-semantic` prints a description, the executable path and the index status for the current directory; in TOON and `--json` they are the `description` and `bin` fields, indexed or not. In an unindexed directory it states `status: not_indexed`, suggests `llm-semantic index .` as the next step and exits 0. |
| 9 | Contextual disclosure (`help[]` next steps) | Met | The default output of the search family, `memory search`, `memory list`, `memory stats`, `multisearch`, `index-status` and the bare run carries a `help` list of suggested next steps, as do the unreachable-embedding-API error, the missing-index error of every command that needs an index (the memory commands point at `memory store`, the rest at `index`) and the unknown-flag, unknown-command and format-conflict errors. |
| 10 | Consistent `--help` on every subcommand | Met | `--help` exits 0 on every subcommand, and an unknown flag or command names it, lists the valid choices and exits 2. The search family, `multisearch`, `index`, `index-update`, `index-status` and `setup` carry 2-3 invocations in an `Examples` section; `callers`, `refs`, `collection delete` and the `memory` subcommands show theirs in the description. The root `-v`/`-V`/`--version` print the bare version and exit 0 on both binaries, also beside the persistent flags when no subcommand is named (`--axi -v`); a subcommand's `-v` keeps its own meaning, e.g. `index --verbose`. |

Scope note for rows 2-5: they are met in the default TOON output (and `--plain`, where the note says so). `--json` keeps its pre-AXI schema so existing scripts keep working — full fields, untruncated content, and a bare result array without `total` or a zero-result message (`callers` and `refs` keep their object with `count`; `memory list` keeps the raw entry array, `null` when the store is empty, and `memory stats` keeps its summary object with full rows) — so the machine-readable JSON mode does not meet principles 2-5 and is a standing exception with that reason. It is opt-in: nothing prints it unless `--json` is passed.
