## Principle 6 in detail

- **6a. `index-status` with no index exits 0.** Probed output:
  - `--axi`: `error: index not found` / `indexed: false` on stdout, exit 0.
  - `--json`: `{"error":"index not found","indexed":false}`, exit 0.
  - plain: `Semantic index not found.` on stdout, exit 0.

  Closed by **05 T2**.
- **6b. `--axi` errors are plain text on stderr.** `search foo --axi --index-dir ./nope` prints `Error: semantic index not found...` on stderr with nothing on stdout (exit 1). With `--json` the same error is structured on stdout. The cause: `output.PrintError` has an AXI branch, but it takes the AXI setting from `output.SetDefaultAXI`. Nothing outside `pkg/output/axi_test.go` calls that function, so `cmd/llm-semantic/main.go:23-26` always builds a non-AXI formatter. **Neither 05 nor 05.1 has a task for this.** 05.1 AC2 ("errors follow principle 6, a test asserts an error run") would catch it only if its test runs in `--axi`. Filed as tech debt on the issue. *Since closed:* errors go to stdout in the active format, TOON included ([axi-conformance.md](axi-conformance.md) row 6).
- **6c. Usage errors exit 2, and plain-mode errors go to stderr.** `--bogus` and an unknown subcommand print `Error: unknown flag: --bogus` on stderr and exit 2. This holds in `--axi` mode too (6b). axi.md asks for exit codes 0/1 and errors on stdout. Exit 2 for a malformed invocation is a deliberate go-axi convention (`goaxi.ExitUsage`, `pkg/output/exit.go:52-70`), and stderr is deliberate for plain text (`pkg/output/formatter.go:365-378`). **05.1 T5** must state both as README exceptions with that reason. *Since closed:* errors go to stdout in every mode, `--plain` included, and exit 2 is kept for a malformed invocation ([axi-conformance.md](axi-conformance.md) row 6). Since `v2.0.1` the message names what was wrong and shows the right form, and a bad flag value (`--top 0`, an unknown `--profile` or `--embedder`) and `setup` run in the home directory exit 2 as well, before anything is created or sent.
- **6d. Two commands prompt, and their abort exits 0.** `collection delete` without `--force` (`collection.go:103-118`) and `memory stats --prune` without `--yes` (`memory.go:1396-1409`) print `Are you sure? [y/N]` and read stdin. On a TTY that is an interactive prompt. On closed stdin they print `Aborted...` and return nil, so a deletion that did not happen exits 0. **Neither 05 nor 05.1 has a task for this.** Filed as tech debt on the issue. *Since closed:* neither command prompts; each refuses with an error naming `--force` or `--yes` and exits 1 ([axi-conformance.md](axi-conformance.md) row 6). Re-probed at `v2.0.1`: unchanged, and `collection delete --profile bogus --force`, which exited 0 at `v2.0.0`, now exits 2 naming the profile.

Idempotency of mutations (`index`, `index-update`, `memory`) was not probed. It needs an embedding endpoint, and none exists on the build host.
