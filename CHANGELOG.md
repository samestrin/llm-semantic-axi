## [1.2.0] - 2026-11-12

### Added

- `skills/llm-semantic/SKILL.md`: the Agent Skill is committed in the repository, so `npx skills add samestrin/llm-semantic-axi --skill llm-semantic` installs it without running `setup`. It is byte-identical to the skill `llm-semantic setup` writes into `.claude/skills/llm-semantic/`, and a test fails when the two differ.
- `docs/demo/`: a VHS tape and its rendered GIF (22.6 s) of a real session — `--version`, `search "retry embedding requests with backoff" --axi --top 3`, and `callers EnrichForEmbedding --axi` — with a README giving the render command, the embedding endpoint and index the session needs, and the timing of the committed render.
- `docs/release-checklist.md`: release steps for re-rendering the demo after its commands change and regenerating the committed performance results with `make bench-perf-write`.

### Changed

- README: rewritten to the README standard. It now covers every install path (installer, release archive with its checksum, `go install`, from source, `setup`, `npx skills add`), a quick start, configuration, output modes and exit codes, and limits. It also corrects the profile paragraph: a profile is separate only when it has its own `--index-dir` or Qdrant collection.
- README: the reference material moves into `docs/` — `docs/languages.md` (the language table and the call-edge limits), `docs/staleness.md` (how the search family reports an index behind the working tree) and `docs/axi-conformance.md` (the ten-principle table and its `--json` scope note). The README keeps a summary of each, still states that an empty `callers` answer in a language with no recorded edges means "not indexed for edges", not "no callers", and gains a Documentation section linking every page, `docs/axi-audit.md` included as history. `TestReadmeLanguageTable_MatchesRegisteredExtensions` now reads `docs/languages.md`, and new tests fail if a call-edge "not proof" sentence, a Documentation link or a conformance row goes missing.
- The Agent Skill text — both the committed `skills/llm-semantic/SKILL.md` and the copy `setup` writes — says `callers` and `refs` work for Go, JavaScript, TypeScript, Python and Rust. It said "for Go only" and described "a Go symbol", which told an agent the other four languages have no call graph. An empty result for any other language still means not indexed, not that none exist.
- A wrong number of positional arguments (`llm-semantic search` with no query, `refs` with no symbol, `index a b`) exits 2 as a malformed invocation instead of 1. Under `--json` the error is printed on stdout as `{"error": true, "message": ...}` (minimal under `--min`), as it already was under `--axi`; before, stdout was empty. An unknown flag under `--json` is reported on stdout the same way.
- A bare `llm-semantic` run in a directory with no index reports the state instead of failing: plain output prints the description, executable path, `Status: not_indexed` and `Indexed: false` with the hint to run `llm-semantic index .`; `--json` / `--axi` carry `bin`, `description`, `status: not_indexed`, `indexed: false` and (under `--axi`) a `help[]` list. It exits 0 and creates no `.index`. `index-status` in the same directory still exits 1, and an index that exists but cannot be read still fails with exit 1.
- README: the AXI conformance table is restated against the current binaries. TOON (row 1) is an exception, opt-in through `--axi`; ambient context (row 7) is an exception, `setup` targeting Claude Code only with no session-end hook; content-first (row 8) and `--help` (row 10) notes name the current behaviour — a bare run in an unindexed directory states `not_indexed` and exits 0, unknown flags and commands are named with the valid choices at exit 2, and the root version flags print the bare version and exit 0. The bare-run comment in Usage is rewritten to match.
- An unknown flag (`llm-semantic search --bogus`) is rejected by name with every flag that command accepts and a pointer to its `--help`, exit 2; an unknown subcommand lists the valid commands the same way. Under `--axi` the error is TOON on stdout with `help[]`; plain mode keeps stderr. `llm-semantic memory bogus` and `collection bogus` now fail with exit 2 instead of printing help and exiting 0.
- `llm-semantic-mcp -v`, `-V` and `--version` print the bare version and exit 0 without starting the server or needing the CLI binary, and the started banner prints the version once (it printed `vv1.2.0` for a release build).
- `llm-semantic -v`, `-V` and `--version` print the bare version (`dev` for an unstamped build) and exit 0, without the commit suffix. `-v` after a subcommand is unchanged: `index -v` is still `--verbose`.
- A resumed `index` reports the files it skipped as unchanged that were chunked as text windows, and `index-status` lists them (`files_fallback`, `fallback_files`, `fallback_chunker_failed_files` under `--json` / `--axi`); the reason is now stored with each file's hash. An index built before this records it as each file is next re-indexed. (technical debt)
- Staleness in `callers`, `refs` and the searches is measured against the directory that was indexed, now recorded with the last index, so `--index-dir` pointing at another repository's index reports how far that repository has moved instead of `unknown`. An index recorded before this keeps measuring from the working directory until it is re-indexed. (technical debt)
- `index-update` in git mode keeps a changed file's old chunks when its re-index fails, so a file named in the errors stays searchable as it was last indexed; `index --json` and `index-update --json` print `"errors": []` on a clean run instead of `null`. (technical debt)
- `callers` reports `not_indexed_for_edges` for a language whose index holds import edges but no call edges, instead of "none recorded in the call graph". (technical debt)

## [1.1.0] - 2026-11-10

### Added

- TypeScript `namespace X { ... }` and `declare module "x" { ... }` bodies are walked now, so the declarations inside them are indexed instead of missing while the file read as cleanly parsed. A JavaScript or TypeScript class field holding an arrow function or a function expression (`bar = () => {}`) is indexed as a `method`; before, only the enclosing class was.
- Qdrant collections now record the storage contract version in a `storage_contract` point, written when the collection is created and stamped onto older collections on their next open. Opening a collection stamped with a different version fails with a clear error instead of reading it under the wrong shapes. `List` no longer returns bookkeeping points as chunks. Additive: `contract_version` stays 1.
- Rust call edges: the tree-sitter Rust chunker records `calls` edges for a bare-name call (`helper()`, `helper::<T>()`) and for `self.f()` when the caller's own `impl` or trait defines a method `f`, and `imports` edges for each `use` (named by its last path segment, aliases ignored, a wildcard names nothing). Other receivers (`obj.f()`), path calls (`Type::f()`, `Self::f()`) and macros record no edge, and there are no `uses_type` edges. A call in an inline `mod` body or in a `const` or `static` initialiser has no function to belong to and records no edge, and neither does a `self.f()` whose `f` is defined in a second `impl` block; nothing tracks that last miss. An index built before this change gains Rust edges only after `index --force`.
- README: the language table marks Rust (`.rs`) as having call edges, and the known-limit section states which Rust calls are recorded and which are not, alongside the JavaScript, TypeScript and Python paragraphs. The table guard test now allows Rust to claim call edges.

### Changed

- `multisearch --output by_query` / `by_collection` in plain-text mode now renders the grouped results (a heading per query or collection, then the same per-result lines); before, only the `Multisearch: N queries, M results` header printed, because the grouped formats leave the blended list empty by design. The `setup` SessionStart hook now runs `llm-semantic index-status || true`, tolerating the non-zero exit a missing index raises so Claude Code no longer shows a hook error in every un-indexed project; existing hooks are upgraded in place on the next setup run.
- `index` and `index-update` no longer report a file whose chunker errored or panicked as `(parse failed)`. The text-window summary prints a separate `(chunker failed)` group, and `--json` / `--axi` name those paths in `fallback_chunker_failed_files`; `fallback_files` still lists every file that fell back.

## [1.0.0] - 2026-11-06

First standalone release, extracted from [samestrin/llm-tools](https://github.com/samestrin/llm-tools). Installs with `install-release.sh` (no sudo, no clone, no Go; checksum-verified) or from source with `install.sh`. Support is best effort (see the README).

### Added

- Token benchmark (`benchmarks/results-tokens.md`): ten fixed searches of this repository at a pinned commit, rendered as `--json`, `--axi` and plain output, with the outputs checked in and counted with a vendored `cl100k_base` tokenizer (an approximation of any given model's tokenizer). `make bench-tokens` re-counts them offline and fails if the file's numbers disagree; `make bench-generate` regenerates the outputs against a local stand-in embedder. On these searches `--axi` prints 28.4% of the tokens `--json` prints, and plain output 15.5%, because plain shows the least of each result.
- Download install path: each release publishes `llm-semantic-<os>-<arch>.tar.gz` holding both binaries for Linux and macOS (amd64, arm64), listed in `SHA256SUMS.txt`, plus `install-release.sh`. The installer needs no sudo, no clone and no Go: it downloads with timeouts, refuses an archive whose checksum is missing or wrong, and installs `llm-semantic` and `llm-semantic-mcp` together into `~/.local/bin` (`--dir` to change it, `--version` to pin a release, `--base-url` to point at a mirror). A failed or interrupted run leaves the existing binaries untouched. It warns when the install directory is not on `PATH`, because `llm-semantic-mcp` finds the CLI through `PATH`. `install.sh` (build from source) is unchanged.
- README: the install section now leads with the release download installer (`install-release.sh`, no sudo, no clone, no Go), states the `~/.local/bin` PATH requirement (`llm-semantic-mcp` finds the CLI through `PATH`), and keeps the source build as the alternative. The storage and embedding setup steps are spelled out: sqlite is the default and needs nothing, Qdrant is configured through `QDRANT_API_URL` / `QDRANT_API_KEY`, and an OpenAI-compatible embedding endpoint must be set through `--api-url` / `--model` or the `LLM_SEMANTIC_API_URL` / `LLM_SEMANTIC_MODEL` environment variables before indexing.
- README: the language table marks every JavaScript and TypeScript extension (`.js` `.jsx` `.mjs` `.cjs` `.ts` `.tsx` `.mts` `.cts`) as having call edges, and the known-limit section says which calls are recorded (bare name or `this.` receiver only). The Python row is marked `yes` too, with its own recorded-calls paragraph (bare name, `self.`/`cls.`, imports; innermost function). An index built before the JS/TS or Python edges needs `index --force`.
- Python call edges: the tree-sitter Python chunker records `calls` edges for bare-name calls and `self.`/`cls.` method calls, and `imports` edges for each imported module or name, so `callers` and `refs` answer for `.py`, `.pyw` and `.pyi` files. There are no `uses_type` edges for Python, and a call is recorded against the innermost function or method, never its enclosing class. An index built before this change gains Python edges only after `index --force`.
- C++ chunker: a `typedef` is indexed under its declarator name as a `struct` chunk covering the whole typedef, so `typedef struct { int x; } P;` is found as `P`. A bare nameless `struct {..} v;` is still not chunked.
- The MCP server runs the CLI with `--axi` instead of `--json --min`, so tool results reach the model as TOON.
- `--axi` output of `search`, the profile search aliases and `multisearch` shows four fields per result (`file` as `path:line`, `name`, `score`, `content` cut at 200 characters with a size hint), and `memory search` shows `id`, `question`, `score`, `answer`. `--full` returns every field and the whole text; `--json` and plain output are unchanged.
- `--axi` output of `search`, the profile search aliases, `memory search`, `multisearch` and `index-status` carries a `help` list of suggested next steps, and the missing-index error does too. `--json` and plain output are unchanged.
- Standalone repository, extracted from [samestrin/llm-tools](https://github.com/samestrin/llm-tools). `internal/semantic`, `cmd/llm-semantic`, `cmd/llm-semantic-mcp` and the used slice of `pkg/output` move across unchanged.
- `Makefile` with `build`, `build-all`, `test`, `test-race`, `test-cover`, `lint`, `vet`, `fmt`, `install`, `clean` and `hooks` targets. `llm-tools` had no semantic build targets at all, so this is new rather than copied.
- CI: `lint` → `test -race` → `coverage`, chained by `needs:`, plus a five-platform cross-compile matrix and a tag-triggered release workflow.
- `.golangci.yml` matching the selection used across `samestrin/atcr` and `samestrin/go-axi`.
- Parse-error fallback for the tree-sitter chunkers: when a file's parse tree has an error, the functions and classes still parsed are kept and every other non-blank line is indexed as generic text windows (a chunker failure or panic windows the whole file). `index` and `index-update` print `Chunked N files as text windows (parse failed):` with the paths, and `--json` / `--axi` carry `FilesFallback` and `FallbackFiles` (`files_fallback`, `fallback_files` for `index-update`).
- C chunker (`.c`): functions, structs, unions, enums and typedefs are indexed with names and line ranges, including definitions inside `#ifdef`. `.h` is left to the C++ chunker.
- Java chunker (`.java`): classes, enums and records are `struct` chunks, interfaces and annotation types are `interface` chunks, and methods and constructors (including interface method declarations) are `method` chunks, with annotations kept in the content and dropped from the signature. Java files were previously skipped. Like every non-Go language, Java emits no call edges, so an empty `callers`/`refs` for a Java file means "not indexed".
- TypeScript chunker for `.ts`, `.tsx`, `.mts` and `.cts`. `.tsx` is parsed with the TSX grammar, so React components index as functions and classes instead of falling back to text windows; `.mts` and `.cts` files, previously skipped, are now indexed. Abstract classes, enums and `export default class` are chunked too. The JavaScript chunker keeps `.js`, `.jsx`, `.mjs` and `.cjs`.
- Tree-sitter C++ chunker for `cpp`, `cxx`, `cc`, `hpp`, `hxx`, `hh` and `h`. Functions, classes, structs, unions, enums, namespaces and `extern "C"` blocks become named chunks with line ranges; a template's range includes its `template <...>` header; out-of-line `Foo::bar` definitions are methods. `.h` is registered here once (the C++ grammar parses C headers); a header it rejects falls back to text windows. Like every non-Go chunker it emits no call edges, so `callers` and `refs` return empty for C++ files.
- Ruby chunker (`.rb`): classes are `struct` chunks, modules are `file` chunks (the type the Rust and C++ chunkers give a namespace), and `def` is a `method` inside a class or module and a `function` at top level. `def self.x`, methods in `class << self`, `private def x`, endless defs and scoped `class A::B` names are covered. Ruby files were previously skipped. Like every non-Go chunker it emits no call edges, so `callers` and `refs` return empty for Ruby files.
- C# chunker (`.cs`): block and file-scoped namespaces are `file` chunks (a file-scoped `namespace X;` runs to the end of the file), classes, structs, records and enums are `struct` chunks, interfaces are `interface` chunks, and methods, constructors and destructors are `method` chunks, with attributes kept in the content and dropped from the signature. `.cs` files were previously skipped. A tree in which gotreesitter dropped declarations without marking an error is treated as a parse error, so the lost lines are indexed as text windows instead of vanishing. Like every non-Go chunker it emits no call edges, so `callers` and `refs` return empty for C# files.
- Kotlin chunker for `.kt` and `.kts`: classes, enum classes, objects and companion objects (an unnamed one as `Companion`) are `struct` chunks, interfaces and `fun interface` are `interface` chunks, functions are `function` chunks at file scope and `method` chunks inside a type, and secondary constructors are methods named after their class. A bare file-scope `object Name { }`, which the grammar parses as an expression, and a file-scope annotation with arguments, which it detaches from its declaration, are both handled. Kotlin files were previously skipped. Like every non-Go chunker it emits no call edges, so `callers` and `refs` return empty for Kotlin files.
- `docs/storage-contract.md`: storage contract (`contract_version: 1`) for the Qdrant collection, linked from the README's "For integrators" section. It covers all five point kinds (chunk, `file_hash`, `calibration_metadata`, memory, `retrieval_log`), their payload keys and value shapes with per-line citations to the writing code, and the filter rule that chunks are exactly the points carrying `chunk_id`. The sqlite backend (`.index/semantic.db`) is documented as internal and out of scope.
- `docs/storage-contract.md` gains a "Bumping this contract" section: a breaking change raises the document's `contract_version` and is listed in this changelog; additive changes (new payload key, new point kind, documenting an existing shape) do not bump it.
- README language table covering every extension `RegisterAllChunkers` registers (language, extensions, chunker, call edges), replacing the stale chunker list under "Known limit". `TestReadmeLanguageTable_MatchesRegisteredExtensions` fails when an extension is registered without a row, a row names an unregistered extension, or a non-Go row claims call edges.
- README gains an "AXI conformance" section: a table of the ten axi.md principles, each marked met or stated as an exception with its reason (usage errors exiting 2, plain-mode errors on stderr, the two commands that still prompt, and a scope note that principles 2-5 are met in `--axi`/plain only — `--json` keeps its pre-AXI schema so existing scripts keep working). It is the current record; `docs/axi-audit.md` is now history only.
- `llm-semantic setup`: writes a Claude Code SessionStart hook into the project's `.claude/settings.json` (merged, other keys and hooks kept; refuses a file it cannot parse) and an Agent Skill at `.claude/skills/llm-semantic/SKILL.md`. Prints the paths written, `--dry-run` writes nothing, a second run reports `unchanged`, and it never prompts.
- The Qdrant backend records the commit and time of the last index, as a new `last_index` point kind (`type`, `commit`, `indexed_at`) documented as section 6 of `docs/storage-contract.md`. The point is additive, so `contract_version` stays at 1. A `--force` re-index drops it with the chunks (unlike `calibration_metadata`, which it keeps), as the sqlite backend does.
- The search family (`search`, its profile aliases, `multisearch`, `callers`, `refs`) reports how stale the index is, measured with git against the working tree (the index's own directory is not counted as a change). `--axi` carries a `stale` object (`state` of `fresh`, `stale` or `unknown`, with `commits_behind`, `files_changed`, `indexed_commit`, `indexed_at` when measured and a `reason` when unknown); plain output ends with an `Index is stale: ...` / `Index staleness unknown: ...` line; `--json` and `--min` keep their stdout schema and print the line on stderr. A fresh index prints no line. `memory search` reports `state: not_applicable`. The sqlite backend records the last index in `index_metadata`.

### Changed

- `collection delete` without `--force` and `memory stats --prune` without `--yes` no longer prompt on stdin. They refuse with an error naming the flag and exit 1, deleting nothing; `--axi` adds the command to run. Before, answering "n" or running with closed stdin printed `Aborted` and exited 0, so a delete that did not happen reported success. Scripts that piped `y` into either command must pass the flag instead. (AXI principle 6)
- `index --json` and `index --axi` now emit snake_case keys (`files_processed`, `files_skipped`, `files_unchanged`, `chunks_created`, `files_fallback`, `fallback_files`, `errors`); before they emitted the Go field names (`FilesProcessed`, ...). Anything that parsed the old keys must change.
- `index-status` with no index now returns a "semantic index not found" error and exits non-zero in plain, `--json` and `--axi` modes. It previously printed a notice (or `{"error":"index not found","indexed":false}`) and exited 0.
- A bare `llm-semantic` run is content-first: instead of help, it prints a one-line description, the executable path (home shown as `~`) and the index status for the current directory. A missing index is the same non-zero error as `index-status`; `--help` still prints help (its usage block gains a `llm-semantic [flags]` line).
- The search family (`search`, `code-search`, `docs-search`, `memory-search`, `multisearch`) states its total and says when it found nothing. Plain output of `search` and `memory-search` opens with `N results for "query"`, and an empty search prints `No results found for "query" (0 results).` instead of `No results found.`. `--axi` output of `search` and `memory-search` is now an object with `query`, `total` and `results`, plus a `message` when there are none; `multisearch --axi` gains the `message`. `--json` and `--min` keep their old shape.
- `memory search` over an empty store no longer prints the same `No results found` words as a search that matched nothing: it says the memory store is empty and names `llm-semantic memory store`, and in `--axi` the answer carries `status: store_empty` (versus `no_match` over a populated store that matched nothing). This change shipped in 1.0.0 without an entry; recorded here retroactively. (technical debt)
- `callers` and `refs` say what an empty answer means. When no edges come back they look up the chunks named the symbol: none reports `symbol not indexed`, a symbol indexed only in a language the index holds no edges for (every non-Go language today) reports `not indexed for edges`, and only an edge-recording language reports `No callers of X recorded in the call graph`. `--axi` carries this as `status` (`symbol_not_indexed`, `not_indexed_for_edges`, `none_recorded`) and `message`; `--json` is unchanged. Before this all three printed `(the symbol may not be indexed)`.
- go-axi moves from **v0.1.2** to **v0.3.0**.
- Eleven direct dependencies that only `internal/support` and `internal/filesystem` used are dropped: `BurntSushi/toml`, `html-to-markdown`, `goquery`, `cascadia`, `expr`, `go-gitignore`, `go-diff`, `gjson`, `sjson`, `match`, `pretty`. Thirteen direct requires remain.
- Both binaries now report the version they were built from. `version` and `commit` in `cmd/llm-semantic`, and `serverVersion` in `cmd/llm-semantic-mcp`, are stamped by `-X` at build time instead of being hardcoded to `1.5.0` and `1.6.0`.
- `serverVersion` changed from a `const` to a `var`. `ldflags -X` rewrites a symbol, and a const has no symbol to rewrite, so the hardcoded value would have silently outlived every tag.

### Fixed

- `index-update` (both `--no-git` and git paths) counts a file it could not process as skipped and names it with its error, in the text output and in `--json`/`--axi` (`files_skipped`, `errors`); before, such a file vanished silently. A store that cannot return a file's hash now counts as a failed file instead of re-indexing it.
- `index` reports progress for an unreadable file (as skipped, with the count of files already done), and the commit-record failure message no longer begins "index updated", which a caller could read as success with a footnote.
- Python recursion is one rule: `self.f()` inside method `f` (and `cls.f()`) now records no self-edge, as `f()` inside `f` already did. A call to a differently named method still records its edge. An index built before this change needs `index --force`.
- `search` with an unquoted multi-word query no longer embeds a trailing space; the query is the arguments joined by single spaces, as `code-search`, `docs-search` and `memory-search` already did.
- `refs` lists every `imports` edge as unresolved. Before, an import linked to any lone chunk of the same name, so `import debounce from "lodash/debounce"` pointed at a local `function debounce` (and Go's `import "net/http"` at a lone `func http`). Re-indexing unlinks imports edges an older index had already linked.
- JavaScript and TypeScript call edges: a `this.get()` call links only to a `get` method of the caller's own class, in the same file. Before, it linked to any lone chunk named `get`, so a method was reported as a caller of a top-level function or of another class's method it can never reach. With no such method, or outside a class, the call stays unresolved in `refs` and is never shown as a caller.
- Re-indexing a file edited to remove a chunk's last call now removes that chunk's old call edges; before, an edit that left a file with no calls at all kept every edge it used to have.
- Opening an index written before the `file_mtime` column existed no longer fails with `no such column: file_mtime`; the migration now runs before the index that references it.
- Qdrant `ReadEmbeddings` reads the `Dense` vector instead of the deprecated flat `Data` field, so a server that sends only `Dense` no longer yields an empty map and forces every unchanged chunk to be re-embedded.
- MCP tool schemas no longer advertise `json` and `min` properties. The server always runs the CLI with `--axi`, so setting either was silently ignored.

- With `--axi`, a failed command now prints its error as TOON (`error: true`, `message: ...`) on stdout and still exits non-zero. Before this it printed a plain `Error: ...` on stderr and left stdout empty, because nothing passed `--axi` to the error formatter. This covers errors from the root command's config checks as well as from the subcommand.
- Plain `multisearch` with `--output by_query` or `by_collection` no longer prints `No results found.` under a header that counts results. The empty check read the blended list, which a grouped format leaves empty; it now reads the total.
- `search`, the profile search aliases and `multisearch` over an index that exists but holds no chunks no longer print `No results found for "..."`, the same words as a search that matched nothing. They say the index is empty and name `llm-semantic index <path>`; in `--axi` the answer carries `status: index_empty` and a `help` list pointing at `index`. An empty answer over a populated index carries `status: no_match`. `--json` is unchanged.
- `llm-semantic-mcp` exits 0 when a client disconnects, including a client that hangs up or stops reading before the server has replied. Before this, a reply that lost that race made the server print `Server error: server is closing: EOF` or `write |1: broken pipe` and exit 1, or be killed by SIGPIPE, so a supervisor saw a normal session end as a crash. A malformed message from the client, or output that fails for any reason other than a closed pipe, still exits 1 and says why.
- The MCP server's instructions now give the real number of tools, taken from the tool definitions. They said 4 while 16 were registered.
- `index-status` on the Qdrant backend no longer reports the moment it was asked as `Last updated`. It reports the recorded time of the last index, and nothing when no index has been recorded; a record it cannot read is an error.
- An `index` or `index-update` in which any file failed to index (an embedding error, an unreadable file) no longer records the last index. It leaves the previous record as it was, so a later search reports the index as behind instead of `fresh` over files that are missing.
- An `index --force` on the Qdrant backend that stops after clearing the collection (cancelled, or an embedding error) no longer leaves the previous last-index record over the partial index. The record is dropped with the chunks, so a later search reports the staleness as unknown (`no_record`), as on sqlite, instead of `fresh` or `stale`.
- `chunks_total` on the Qdrant backend counts only chunk points. It counted every point in the collection, file hashes, calibration metadata and memory entries included, so a calibrated index with no chunks (an `index --force` over a directory with no indexable files) made `search` answer `no_match` instead of `index_empty`. A chunk count that fails is now an error.
