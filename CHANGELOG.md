## [Unreleased]

### Changed

- The AXI catalog entry's `reviewed_revision` is re-pinned to `f021e85`, the commit the `v2.0.1` tag carries. Every `file:line` it cites is moved to where that code sits at the tag, and every probe was re-run on a build of it; it now also cites the MCP server passing tool input after `--` and `setup` refusing the home directory and symlinks out of the project. `docs/axi-audit.md` says when it was re-checked against `v2.0.1` and notes beside rows 1 and 6 and findings 6c and 6d what that release changed.
- The AXI catalog entry's `domain` is `Code navigation / Semantic search`, matching the entry submitted to axi.md (kunchenguid/axi#291).
- `docs/languages.md` now states the remaining JavaScript and TypeScript gaps: calls at module level and through another object record no edge, and only a bare constructor name is recorded. It also states the shared recursion rule: functions and methods record no self-edge, while a bare `f()` inside method `f` keeps its edge to the free function.

### Fixed

- `index docs/ --profile docs` after `index .` now indexes the docs files into `.index/docs` and `docs-search` reads that index, instead of skipping every file as already indexed in the shared `.index` and answering a docs search from code chunks. A profile other than `code` defaults to `.index/<profile>` when neither `--index-dir` nor a config file chose a path; `code` stays at `.index`. There is no migration: an index built under the old shared `.index` is not moved, so rebuild each profile where it now lives (`llm-semantic index --force --profile docs`).
- `collection delete --profile docs --force` removes the `file_hashes` record for each of the profile's files whose chunks are now all gone. SQLite removes the record in the deleting transaction; Qdrant has no transaction, so it removes the hash points first and then the domain's chunks, leaving files `index` re-indexes rather than chunks nothing will re-index if the second delete fails. `index-status` stops listing those files and `index` or `index-update` indexes them again; before, the record survived and the file was skipped as unchanged though its chunks had been deleted. A file that still has chunks under another profile keeps its record and stays skipped there.
- Qdrant's `DeleteByFilePath` returns the chunk count only, not that count plus the `file_hash` point, so an incremental update on Qdrant no longer over-reports `ChunksRemoved` by one per file. SQLite already returned the chunk count.
- `new Foo()` now records a `calls` edge to `Foo` in JavaScript and TypeScript, so `callers Foo` lists the constructing function; before, a construction wrote no edge. Only a bare constructor name is recorded (`new a.Foo()` stays unrecorded); an index built before this change needs `index --force`.
- `require("x")`, dynamic `import("./m.js")` and re-exports (`export { a } from "./x"`, `export * from "./x"`, `export type { T } from "./x"`) now record `imports` edges in JavaScript and TypeScript. Before, `require("x")` was recorded as `calls require`, so `callers require` listed every CommonJS file, and dynamic imports and re-exports wrote no edge at all. Only a static module path is recorded (a string literal, or a template literal with no `${...}`); `require(variable)` records nothing rather than a guessed name. Import names also drop a dotted suffix: `./a.test` is recorded as `a`, not `a.test`. Imports are never resolved to chunks; the name is what `refs` displays, so the suffix no longer shows up in its output. An index built before this change needs `index --force`.
- `collection delete --profile docs --force` deletes from the docs profile's own index, `.index/docs` (Qdrant collection `docs`), the same one `index --profile docs` writes. It opened `.index`, printed `No chunks found for domain 'docs'`, exited 0 and left every docs chunk in place. With no index for the profile it now fails with `no index for profile 'docs' at .index/docs: nothing was deleted`. An explicit `--index-dir` or a loaded config keeps its path, and the delete uses the profile's configured backend (`docs_storage`), where it used the code profile's.
- Recursion is one rule in Go, Python, Rust, JavaScript and TypeScript, so one program gives the same `callers` answer in each. `f()` inside function `f`, and a receiver call such as `this.f()`, `self.f()`, `cls.f()` or Go's `r.f()` inside method `f`, write no self-edge; before, JavaScript and TypeScript recorded `f calls f` and `f calls this.f`, and Go recorded `f calls r.f`. A bare `f()` inside method `f` calls the free function `f` and now keeps its edge; Go, Python and Rust dropped it, so `callers f` missed that caller. An index built before this change needs `index --force`.
- A failed reranker is now stated beside the fallback results: TOON reports `status: reranker_failed` and a `help` entry, and `--plain` prints a separate `reranker failed: ...` line. `--json` prints that line to stderr while stdout stays a bare array; the caller's `--threshold` still filters the embedding-ranked results, and the search exits 0 because results exist.

## [2.0.1] - 2026-11-23

### Security

- The MCP tools no longer let tool input become a CLI option. `llm_semantic_index` with `{"path":"--api-url=http://host"}` sent the project's files to that endpoint (when `LLM_SEMANTIC_API_URL` was unset in the server's environment), and `{"path":"--allow-home"}` bypassed the home-directory refusal. Every path, query, symbol and id a tool passes as a positional now follows a `--`, and a value starting with `-` is refused before the CLI runs.
- The index is not written through a symlink. A `.index` linked outside the project was followed and the SQLite database written there (an empty file it pointed at became a database); `index`, `index-update`, `search` and every other command that opens the index refuse a symlinked index directory, `semantic.db`, or its `-wal`, `-shm` or `.lock` file.
- Indexing a directory holding several repositories (with `--allow-home`) honours each nested repository's `.git/info/exclude`; only the outermost one's was read, so a file a nested repository excluded was sent.
- `memory store -f` refuses a path that is a symlink, and an existing file unless `--force` is given; it overwrote the file, or the symlink's target, without asking.
- `index` and `index-update` no longer send secrets, ignored files or files outside the project to the embedding API. They honour `.gitignore` (at every level, including the repository's above the indexed directory) and `.git/info/exclude`; skip hidden directories below the root; withhold files named like credentials (`credentials*`, `secret*` and `service-account*` data files, `.env*`, keys, certificates, `*.tfstate`, `*.log`); read only regular files, following a symlink only to a file inside the root; and withhold files over 1 MiB or with a NUL byte in their first 8000 bytes. Before, a bare `index` run from `$HOME` sent `.config/gh/hosts.yml` (a GitHub token) and `.docker/config.json`, a symlink to a file outside the folder was read and sent, and a FIFO or a `/dev/zero` symlink named `*.txt` hung the run. Withheld files are counted by reason in `files_withheld`, and `--plain` prints a `Withheld N files` line. `index-update --no-git` removes a file that is now withheld from the index.
- `index` refuses your home directory and `/` (exit 2) unless `--allow-home` is given.
- Credentials in the embedding API URL are no longer printed. `--api-url` / `LLM_SEMANTIC_API_URL` set to `http://user:pass@host/?api-key=K` showed the whole URL in the unreachable-endpoint `message` and `help`; they show the scheme, host and path. A cancelled request's error and the reranker's send error drop them too.
- `setup` refuses a `.claude`, `.codex` or `.opencode` path (or any part of it) that is a symlink out of the project, instead of writing through it, and refuses to run in the home directory (exit 2), where it wrote the global `~/.claude` and `~/.codex` configuration.

### Fixed

- `search`, `code-search` and `docs-search` treat a bad `--fusion-k` (below 1), `--fusion-alpha` (outside 0-1), `--recency-factor` (below 0) or `--recency-decay` (0 or less) as a usage error that exits 2. With `--hybrid` or `--recency-boost` they exited 1; without, they were silently accepted.
- `memory import --source` reads only a regular file up to 16 MiB. `--source /dev/zero` hung.
- When every retry of an embedding request got a 5xx, the error said `http: read on closed response body`, or `cannot reach the embedding API` because the retry sent an empty body; it now says `API error: status 503: <the API's message>`, and each retry resends the request.
- `setup` refuses a settings file holding more than one JSON value (exit 1, nothing written). It kept `{"a":1}` and silently dropped a following `{"b":2}`.
- The embedding request path is joined to the base URL's path, so a base URL with a query (`http://host/?api-key=K`) requests `/v1/embeddings?api-key=K` instead of putting the path inside the query, and a trailing `/` no longer doubles the slash. The reranker URL is joined the same way.
- A bad flag value is a usage error that exits 2 before anything is created or sent: an unknown `--embedder` (`index . --embedder bogus` created `.index` and exited 1), an unknown or empty `--profile` (`collection delete --profile bogus --force` exited 0; `index` and `search` accepted it), an unknown `--profiles` entry or `--output`, `--top` below 1, `--threshold` or `--rerank-threshold` outside 0-1, `--older-than` outside 1-36500, a negative `--batch-size`, `--parallel`, `--embed-batch-size`, `--overlap-lines` or `--rerank-candidates`, and an empty `memory store --question` or `--answer`. The message names the flag, the value and what it takes. Because `--profile` is checked, `collection delete`'s help line can no longer carry an unquoted shell command.
- The MCP tools' `top_k` schemas declare `minimum: 1`, and a `top_k` of 0 or less is not forwarded, so the CLI's default applies instead of the `--top` usage error.
- `--index-dir '~/idx'` expands `~/` to the home directory; it created a directory literally named `~`. `index '~'` expands it too.
- The Agent Skill no longer loops on `stale`: it said `index-update` fixes it, but `index-update` applies only the last commit's changes, so an index several commits behind or with untracked files stayed stale. It now says to run `index-update --no-git`, which rescans every file, and that uncommitted files keep the state `stale` until they are committed.
- The README Quick start `index` and `callers` output is re-captured from this release's tree (336 files, 3,822 chunks).
- With no embedding API listening, `search`, `memory search`, `index` and `index-update` said `cannot reach the embedding API at <url> (connection refused)` instead of Go's `failed to send request: Post "...": dial tcp ...` error, and TOON output carries a `help` list: start the embedder, or set `--api-url` / `LLM_SEMANTIC_API_URL` to one that is running (for a hosted `--embedder`, check that its URL is reachable). `index` and `index-update` put the message and help in their one failure document, and the per-file `errors` read the same way. A cancelled request is not reported as unreachable. `--json` keeps its keys.
- The bare `llm-semantic` run carries `bin` and `description` in TOON and `--json` when the directory is indexed too, as `docs/axi-conformance.md` row 8 says; only the unindexed run had them. `index-status` is unchanged.

It counted only memories that had been retrieved, so after one `memory store` it said `total_memories: 0` while `memory list` said `total: 1`, and `--plain` said `No memories found.`; `--plain` now prints the totals and says no retrievals are recorded yet.

## [2.0.0] - 2026-11-16

### Added

- `llm-semantic setup` registers Claude Code, Codex and OpenCode by default; repeat `--target claude|codex|opencode` to select only some targets. Codex gets a merged `.codex/hooks.json` SessionStart hook and `[features] hooks = true` in `.codex/config.toml`; OpenCode gets `.opencode/plugins/llm-semantic.ts`, which adds index status when a session is created. Hooks use `llm-semantic` from `PATH`, or the running binary's absolute path when it is not on `PATH`; rerunning `setup` after moving the binary repairs them. Existing configuration is preserved, repeat runs leave the files unchanged, and `--dry-run` reports without writing.

### Changed

- **Breaking:** the Go module path is `github.com/samestrin/llm-semantic-axi/v2`, because Go ignores a v2 tag on a path without `/v2`. Install with `go install github.com/samestrin/llm-semantic-axi/v2/cmd/llm-semantic@latest` (and `.../v2/cmd/llm-semantic-mcp@latest`); the old path without `/v2` stops at v1.2.0. Code importing `pkg/output` imports `github.com/samestrin/llm-semantic-axi/v2/pkg/output`. A test fails if the module path's major differs from the newest release in this changelog or a README `go install` line names another path.
- **Breaking:** CLI output is TOON by default instead of plain text. `--axi` remains accepted as a no-op alias for TOON, `--json` selects the existing JSON schema, and `--min` remains a payload modifier. **Migration:** pass `--plain` to preserve the v1 human-readable text output. Contradictory format flags are usage errors: they exit 2 and report the error on stdout in the selected format. The Agent Skill names the new default and the format flags.

- The token benchmark measures its Plain variant with an explicit `--plain` instead of no flag, and both tables in `benchmarks/results-tokens.md` name that flag. A test fails if any measured mode passes no flag, so no mode is measured as whatever the CLI's default happens to be. The checked-in outputs and every count are unchanged: `make bench-tokens-write` moved only the two flag cells.
- The token benchmark is re-pinned to epic 27's merge commit (`9ff21f6`): every checked-in output under `benchmarks/outputs/` was regenerated by `make bench-generate` with the CLI where TOON is the default and `--plain` selects text, and `benchmarks/results-tokens.md` names the new pin, says `--plain` instead of "or no flag" in its method, and carries the re-counted numbers. The pinned source now includes the benchmark files themselves, so the result mix moved: `--axi` prints 25.7% of the tokens `--json` prints (was 28.4%), plain output 15.4% (was 15.5%).
- `make bench-generate` now writes the same benchmark outputs on every run, so `make bench-tokens` passes after a regeneration. It used to check the pinned commit out at a random temporary path, and the CLI hashes each chunk's path into its id and embeds the path with the chunk, so every run changed every id, moved scores and could flip relevance labels; index calibration's random probe choice and `indexed_at` in `--axi` changed too. The generator now checks out at the fixed path `/tmp/llm-semantic-axi-bench`, runs the CLI with a fixed random seed, and rewrites `indexed_at` to the pinned commit's time. The outputs and `benchmarks/results-tokens.md` were regenerated once with it: `--axi` is 25.9% of `--json` (was 25.7%), plain 15.5% (was 15.4%).
- The README describes `llm-semantic` as a single Go binary for AI agents and people, with [AXI](https://axi.md)-compliant output built for agents to parse.
- The README title is the repository name, `llm-semantic-axi`; the text still says `llm-semantic` wherever it means the command.
- The default TOON output of `callers` and `refs` meets the AXI shape the README promises: a callers row carries `file` (as `path:line`), `name`, `ref`; a refs row carries `file` (as `path:line`), `ref`, `resolved`, `type`, with external references omitting `file`; and both payloads state `total` instead of `count`. Both commands gain `--full` to restore every field, and their `--min` TOON payload states `total` too. `--json` keeps its pre-AXI schema (`count`, full fields) and `--min` its compact rows. The README says "at most four fields per result", and `docs/axi-conformance.md` rows 2 and 4 now cover `callers` and `refs`.
- The default TOON output of `memory list` and `memory stats` meets the same AXI shape. A `memory list` row carries `id`, `question`, `status` and the answer cut at 200 characters with a size hint; a `memory stats` row carries `id`, `question`, `retrieval_count`, `avg_score`. Both state a `total`, carry `help` and `stale`, and gain `--full` to restore every field; `memory stats` keeps its `total_memories`, `pending` and `promoted` counts. An empty store prints `status: store_empty` with a message instead of `null` (list) or a bare empty result list (stats); a filter that excludes every entry prints `no_match`, and stats over a store with no retrievals says so without claiming the memories are absent. `--json` keeps its pre-AXI schema (the raw entry array, and the summary object with full rows).
- `refs --min` under TOON is no wider than the default row: it drops `type` and carries `file` as `path:line`, so a resolved reference keeps three fields and an external one two. `--json --min` keeps its compact rows.

### Fixed

- `index` and `index-update` exit 1 when any file fails, instead of 0. Against an unreachable endpoint `index` printed `chunks_created: 0` and the error and exited 0, so a caller checking the status believed the index was built. A partial failure exits 1 too: the output still counts what was indexed and lists each failed file, and under TOON and `--json` the same document carries `error: true` and a `message` (both absent on success, so a clean run's JSON is unchanged); `--plain` prints the summary followed by `Error: ...`.
- `memory store` cuts the answer it echoes back at 200 characters in the default TOON output, with the size hint and a new `--full` flag for the whole text, as every other default output does. The stored answer is never cut, and `--json` still echoes it whole.
- `docs/storage-contract.md` is one line per paragraph instead of hard-wrapped prose.
- Errors now print on stdout in the active output format, including `--plain`, on the same stream as successful output. Stderr is reserved for diagnostics.
- The `--axi` next step after a search hit says `callers` and `refs` show call sites for Go, JavaScript, TypeScript, Python and Rust. It said Go only.
- `index-update` in git mode reads each changed file's fallback reason on its own. It listed every fallen-back file in the index once per changed file, so an update cost grew with the size of the index times the number of changed files.
- `docs/storage-contract.md` cites the functions that write each point and key instead of line numbers, which had drifted (`SetFileHash` was cited about 100 lines from where it is). A test fails on a line-number citation or a cited symbol that no longer exists.
- A flag-group usage error, such as `memory stats --prune` without `--older-than`, exits 2 instead of 1 and carries a `help` line pointing at the command's `--help`, like every other malformed invocation. cobra's required-together, one-required and mutually-exclusive group errors are all classified as usage errors.
- The token benchmark labels the TOON row `(default)` instead of `--axi`, which is a no-op alias, and its summary says "the default TOON output". The counts are unchanged.
- `docs/axi-catalog-entry.yaml` quotes the current token totals (11,241 TOON vs 43,477 `--json`, 25.9%), and a test fails if they drift from the recount. `docs/axi-conformance.md` and the catalog entry state that no session-end hook is installed, that the truncation limit is 200 characters, below axi.md's 500-1,500, and that there is no `--fields` flag. The README's bare-run row shows the TOON `status: not_indexed`.
- `--full` help on `search`, the profile search aliases, `multisearch` and `memory search` no longer says "With --axi": TOON is the default, so it reads "Return every field and the whole content of each result". The `--min` help on `search`, `multisearch` and `memory search` says it shapes TOON or JSON, as the root `--min` help and the README do; it said "Output minimal JSON format". A test fails if any flag's help other than `--axi` names `--axi`, or a `--min` help names JSON without TOON.
- The README Output table says a zero-result `--json` search prints `null`, or `[]` when reranking is on. The tests that build a workspace clear the embedder and reranker environment variables, so a developer with `LLM_SEMANTIC_RERANKER_API_URL` set no longer sees six zero-result search tests fail.
- The README Output table states the verified zero-result `--json` conditions: `null` when the store returns nothing, `[]` when reranking or `--hybrid` fusion removes every result, and `--min` always prints `[]` when empty. It said `[]` appears only "when reranking is on". Tests pin each condition against a real index and a fake reranker.
- `docs/axi-catalog-entry.yaml`: every "How each source observation was checked" line reference is re-checked against the source this release ships, and the tag-commit note now marks `c7645ab` as stale and says the observations were re-checked against `d2da5e1` plus these fixes. `reviewed_revision` is left for the owner to set to the v2.0.0 tag commit.
- The demo tape runs `search` and `callers` without the no-op `--axi`. The committed GIF is still the v1.2.0 render that types `--axi`; `docs/demo/README.md` says so until it is re-rendered against a live embedding endpoint. The README Performance section is re-measured on this release with `make bench-perf-write`.
- The missing-index error of `callers`, `refs`, `memory search`, `memory list`, `memory stats`, `memory promote`, `memory delete`, `index-update` and `collection delete` carries a `help` list of next steps under TOON, as `docs/axi-conformance.md` row 9 promises for every missing-index error. The memory commands point at `memory store`, which creates their index; the rest point at `index` and `index-status`.
- `callers` no longer prints identical duplicate rows when one function calls a symbol several times: edges that share a caller are deduped, and the total counts callers, not call sites. Edges still carry the caller's definition line; reporting the call-site lines themselves is a separate change.

A malformed message from the client, or output that fails for any reason other than a closed pipe, still exits 1 and says why.
- The MCP server's instructions now give the real number of tools, taken from the tool definitions. They said 4 while 16 were registered.
- `index-status` on the Qdrant backend no longer reports the moment it was asked as `Last updated`. It reports the recorded time of the last index, and nothing when no index has been recorded; a record it cannot read is an error.
- An `index` or `index-update` in which any file failed to index (an embedding error, an unreadable file) no longer records the last index. It leaves the previous record as it was, so a later search reports the index as behind instead of `fresh` over files that are missing.
- An `index --force` on the Qdrant backend that stops after clearing the collection (cancelled, or an embedding error) no longer leaves the previous last-index record over the partial index. The record is dropped with the chunks, so a later search reports the staleness as unknown (`no_record`), as on sqlite, instead of `fresh` or `stale`.
- `chunks_total` on the Qdrant backend counts only chunk points. It counted every point in the collection, file hashes, calibration metadata and memory entries included, so a calibrated index with no chunks (an `index --force` over a directory with no indexable files) made `search` answer `no_match` instead of `index_empty`. A chunk count that fails is now an error.

### Coverage gate

CI fails below 80% total coverage rather than printing a percentage and moving on. The sibling repo only echoes the number, which is how its coverage drifted unobserved.
