# Changelog

All notable changes to this project are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- C++ chunker: a `typedef` is indexed under its declarator name as a `struct` chunk covering the whole typedef, so `typedef struct { int x; } P;` is found as `P`. A bare nameless `struct {..} v;` is still not chunked. (epic 09)
- The MCP server runs the CLI with `--axi` instead of `--json --min`, so tool results reach the model as TOON. (epic 05.1)
- `--axi` output of `search`, the profile search aliases and `multisearch` shows four fields per result (`file` as `path:line`, `name`, `score`, `content`), and `memory search` shows `id`, `question`, `score`, `answer`, cutting text over 200 characters with a note of how many characters were left out. `--full` returns every field and the whole text. `--json` and plain output are unchanged. (epic 05.1)
- `--axi` output of `search`, the profile search aliases, `memory search`, `multisearch` and `index-status` carries a `help` list of suggested next steps, and the missing-index error does too. A search with results points at `callers`/`refs` and narrowing flags; an empty one says how to widen it. `--json` and plain output are unchanged. (epic 05.1)
- Standalone repository, extracted from [samestrin/llm-tools](https://github.com/samestrin/llm-tools). `internal/semantic`, `cmd/llm-semantic`, `cmd/llm-semantic-mcp` and the used slice of `pkg/output` move across unchanged.
- `Makefile` with `build`, `build-all`, `test`, `test-race`, `test-cover`, `lint`, `vet`, `fmt`, `install`, `clean` and `hooks` targets. `llm-tools` had no semantic build targets at all, so this is new rather than copied.
- CI: `lint` → `test -race` → `coverage`, chained by `needs:`, plus a five-platform cross-compile matrix and a tag-triggered release workflow.
- `.golangci.yml` matching the selection used across `samestrin/atcr` and `samestrin/go-axi`.
- Parse-error fallback for the tree-sitter chunkers: when a file's parse tree has an error, the functions and classes still parsed are kept and every other non-blank line is indexed as generic text windows (a chunker failure or panic windows the whole file). `index` and `index-update` print `Chunked N files as text windows (parse failed):` with the paths, and `--json` / `--axi` carry `FilesFallback` and `FallbackFiles` (`files_fallback`, `fallback_files` for `index-update`). (epic 02)
- C chunker (`.c`): functions, structs, unions, enums and typedefs are indexed with names and line ranges, including definitions inside `#ifdef`. `.h` is left to the C++ chunker. (epic 02)
- Java chunker (`.java`): classes, enums and records are `struct` chunks, interfaces and annotation types are `interface` chunks, and methods and constructors (including interface method declarations) are `method` chunks, with annotations kept in the content and dropped from the signature. Java files were previously skipped. Like every non-Go language, Java emits no call edges, so an empty `callers`/`refs` for a Java file means "not indexed". (epic 02)
- TypeScript chunker for `.ts`, `.tsx`, `.mts` and `.cts`. `.tsx` is parsed with the TSX grammar, so React components index as functions and classes instead of falling back to text windows; `.mts` and `.cts` files, previously skipped, are now indexed. Abstract classes, enums and `export default class` are chunked too. The JavaScript chunker keeps `.js`, `.jsx`, `.mjs` and `.cjs`. (epic 02)
- Tree-sitter C++ chunker for `cpp`, `cxx`, `cc`, `hpp`, `hxx`, `hh` and `h`. Functions, classes, structs, unions, enums, namespaces and `extern "C"` blocks become named chunks with line ranges; a template's range includes its `template <...>` header; out-of-line `Foo::bar` definitions are methods. `.h` is registered here once (the C++ grammar parses C headers); a header it rejects falls back to text windows. Like every non-Go chunker it emits no call edges, so `callers` and `refs` return empty for C++ files. (epic 02)
- Ruby chunker (`.rb`): classes are `struct` chunks, modules are `file` chunks (the type the Rust and C++ chunkers give a namespace), and `def` is a `method` inside a class or module and a `function` at top level. `def self.x`, methods in `class << self`, `private def x`, endless defs and scoped `class A::B` names are covered. Ruby files were previously skipped. Like every non-Go chunker it emits no call edges, so `callers` and `refs` return empty for Ruby files. (epic 02.1)
- C# chunker (`.cs`): block and file-scoped namespaces are `file` chunks (a file-scoped `namespace X;` runs to the end of the file), classes, structs, records and enums are `struct` chunks, interfaces are `interface` chunks, and methods, constructors and destructors are `method` chunks, with attributes kept in the content and dropped from the signature. `.cs` files were previously skipped. A tree in which gotreesitter dropped declarations without marking an error is treated as a parse error, so the lost lines are indexed as text windows instead of vanishing. Like every non-Go chunker it emits no call edges, so `callers` and `refs` return empty for C# files. (epic 02.1)
- Kotlin chunker for `.kt` and `.kts`: classes, enum classes, objects and companion objects (an unnamed one as `Companion`) are `struct` chunks, interfaces and `fun interface` are `interface` chunks, functions are `function` chunks at file scope and `method` chunks inside a type, and secondary constructors are methods named after their class. A bare file-scope `object Name { }`, which the grammar parses as an expression, and a file-scope annotation with arguments, which it detaches from its declaration, are both handled. Kotlin files were previously skipped. Like every non-Go chunker it emits no call edges, so `callers` and `refs` return empty for Kotlin files. (epic 02.1)
- `docs/storage-contract.md`: storage contract (`contract_version: 1`) for the Qdrant collection, linked from the README's "For integrators" section. It covers all five point kinds (chunk, `file_hash`, `calibration_metadata`, memory, `retrieval_log`), their payload keys and value shapes with per-line citations to the writing code, and the filter rule that chunks are exactly the points carrying `chunk_id`. The sqlite backend (`.index/semantic.db`) is documented as internal and out of scope. (epic 01)
- `docs/storage-contract.md` gains a "Bumping this contract" section: a breaking change raises the document's `contract_version` and is listed in this changelog; additive changes (new payload key, new point kind, documenting an existing shape) do not bump it. (epic 01)
- README language table covering every extension `RegisterAllChunkers` registers (language, extensions, chunker, call edges), replacing the stale chunker list under "Known limit". `TestReadmeLanguageTable_MatchesRegisteredExtensions` fails when an extension is registered without a row, a row names an unregistered extension, or a non-Go row claims call edges. (epic 02.1)
- README gains an "AXI conformance" section: a table of the ten axi.md principles, each marked met or stated as an exception with its reason (usage errors exiting 2, plain-mode errors on stderr, the two commands that still prompt, and a scope note that principles 2-5 are met in `--axi`/plain only — `--json` keeps its pre-05.1 schema by board decision). It is the current record; `docs/axi-audit.md` is now history only. (epic 05.1)
- `llm-semantic setup`: writes a Claude Code SessionStart hook into the project's `.claude/settings.json` (merged, other keys and hooks kept; refuses a file it cannot parse) and an Agent Skill at `.claude/skills/llm-semantic/SKILL.md`. Prints the paths written, `--dry-run` writes nothing, a second run reports `unchanged`, and it never prompts. (epic 05)
- The Qdrant backend records the commit and time of the last index, as a new `last_index` point kind (`type`, `commit`, `indexed_at`) documented as section 6 of `docs/storage-contract.md`. The point is additive, so `contract_version` stays at 1. A `--force` re-index drops it with the chunks (unlike `calibration_metadata`, which it keeps), as the sqlite backend does. (epic 04)
- The search family (`search`, its profile aliases, `multisearch`, `callers`, `refs`) reports how stale the index is, measured with git against the working tree (the index's own directory is not counted as a change). `--axi` carries a `stale` object (`state` of `fresh`, `stale` or `unknown`, with `commits_behind`, `files_changed`, `indexed_commit`, `indexed_at` when measured and a `reason` when unknown); plain output ends with an `Index is stale: ...` / `Index staleness unknown: ...` line; `--json` and `--min` keep their stdout schema and print the line on stderr. A fresh index prints no line. `memory search` reports `state: not_applicable`. The sqlite backend records the last index in `index_metadata`. (epic 04)

### Changed

- `index-status` with no index now returns a "semantic index not found" error and exits non-zero in plain, `--json` and `--axi` modes. It previously printed a notice (or `{"error":"index not found","indexed":false}`) and exited 0. (epic 05)
- A bare `llm-semantic` run is content-first: instead of help, it prints a one-line description, the executable path (home shown as `~`) and the index status for the current directory. A missing index is the same non-zero error as `index-status`; `--help` still prints help (its usage block gains a `llm-semantic [flags]` line). (epic 05)
- The search family (`search`, `code-search`, `docs-search`, `memory-search`, `multisearch`) states its total and says when it found nothing. Plain output of `search` and `memory-search` opens with `N results for "query"`, and an empty search prints `No results found for "query" (0 results).` instead of `No results found.`. `--axi` output of `search` and `memory-search` is now an object with `query`, `total` and `results`, plus a `message` when there are none; `multisearch --axi` gains the `message`. `--json` and `--min` keep their old shape. (epic 05.1)
- `callers` and `refs` say what an empty answer means. When no edges come back they look up the chunks named the symbol: none reports `symbol not indexed`, a symbol indexed only in a language the index holds no edges for (every non-Go language today) reports `not indexed for edges`, and only an edge-recording language reports `No callers of X recorded in the call graph`. `--axi` carries this as `status` (`symbol_not_indexed`, `not_indexed_for_edges`, `none_recorded`) and `message`; `--json` is unchanged. Before this all three printed `(the symbol may not be indexed)`. (epic 05.1)
- go-axi moves from **v0.1.2** to **v0.3.0**.
- Eleven direct dependencies that only `internal/support` and `internal/filesystem` used are dropped: `BurntSushi/toml`, `html-to-markdown`, `goquery`, `cascadia`, `expr`, `go-gitignore`, `go-diff`, `gjson`, `sjson`, `match`, `pretty`. Thirteen direct requires remain.
- Both binaries now report the version they were built from. `version` and `commit` in `cmd/llm-semantic`, and `serverVersion` in `cmd/llm-semantic-mcp`, are stamped by `-X` at build time instead of being hardcoded to `1.5.0` and `1.6.0`.
- `serverVersion` changed from a `const` to a `var`. `ldflags -X` rewrites a symbol, and a const has no symbol to rewrite, so the hardcoded value would have silently outlived every tag.

### Fixed

- Opening an index written before the `file_mtime` column existed no longer fails with `no such column: file_mtime`; the migration now runs before the index that references it. (epic 11)
- MCP tool schemas no longer advertise `json` and `min` properties. The server always runs the CLI with `--axi`, so setting either was silently ignored. (epic 08)

- With `--axi`, a failed command now prints its error as TOON (`error: true`, `message: ...`) on stdout and still exits non-zero. Before this it printed a plain `Error: ...` on stderr and left stdout empty, because nothing passed `--axi` to the error formatter. This covers errors from the root command's config checks as well as from the subcommand. (epic 05.1)
- Plain `multisearch` with `--output by_query` or `by_collection` no longer prints `No results found.` under a header that counts results. The empty check read the blended list, which a grouped format leaves empty; it now reads the total. (epic 05.1)
- `search`, the profile search aliases and `multisearch` over an index that exists but holds no chunks no longer print `No results found for "..."`, the same words as a search that matched nothing. They say the index is empty and name `llm-semantic index <path>`; in `--axi` the answer carries `status: index_empty` and a `help` list pointing at `index`. An empty answer over a populated index carries `status: no_match`. `--json` is unchanged. (epic 05.1)
- `llm-semantic-mcp` exits 0 when a client disconnects, including a client that hangs up or stops reading before the server has replied. Before this, a reply that lost that race made the server print `Server error: server is closing: EOF` or `write |1: broken pipe` and exit 1, or be killed by SIGPIPE, so a supervisor saw a normal session end as a crash. A malformed message from the client, or output that fails for any reason other than a closed pipe, still exits 1 and says why. (epic 07)
- The MCP server's instructions now give the real number of tools, taken from the tool definitions. They said 4 while 16 were registered. (epic 07)
- `index-status` on the Qdrant backend no longer reports the moment it was asked as `Last updated`. It reports the recorded time of the last index, and nothing when no index has been recorded; a record it cannot read is an error. (epic 04)
- An `index` or `index-update` in which any file failed to index (an embedding error, an unreadable file) no longer records the last index. It leaves the previous record as it was, so a later search reports the index as behind instead of `fresh` over files that are missing. (epic 04)
- An `index --force` on the Qdrant backend that stops after clearing the collection (cancelled, or an embedding error) no longer leaves the previous last-index record over the partial index. The record is dropped with the chunks, so a later search reports the staleness as unknown (`no_record`), as on sqlite, instead of `fresh` or `stale`. (epic 04)
- `chunks_total` on the Qdrant backend counts only chunk points. It counted every point in the collection, file hashes, calibration metadata and memory entries included, so a calibrated index with no chunks (an `index --force` over a directory with no indexable files) made `search` answer `no_match` instead of `index_empty`. A chunk count that fails is now an error. (epic 04)

### Coverage gate

CI fails below 80% total coverage rather than printing a percentage and moving on. The sibling repo only echoes the number, which is how its coverage drifted unobserved.
